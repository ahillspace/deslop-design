# Copy for comprehension and action

Load for substantive copy work, interface states, or claims that need proof.
Write from the reader's task and the available evidence before fitting words into a visual composition.
Maintain the project's terminology, editorial conventions, and voice; adapt tone to the consequence of the moment.
Prefer concrete familiar words while keeping necessary domain terms and qualifications.

| Element | Decision to make |
|---|---|
| Heading | What question does this section answer? |
| Figure caption | What is shown, what matters, and what limits interpretation? |
| Control | What will this action do to which object? |
| Empty state | Is there no data, no match, or no setup, and what can the reader do? |
| Error | What failed, what remains true, and which recovery is actually available? |
| Success | What changed, and is a further step required? |
| Offer | Who is it for, what is included, under which terms, with what supported proof? |

Hypothetical supplied behavior: an import rejects a file with a missing Date column while retaining the chosen file.
Useful error copy: "Import stopped: the Date column is missing. Add that column and choose the corrected file."
Do not say the import succeeded, records were saved, or automatic retry is available unless the implementation proves it.

Edit in separate passes for meaning, support, and fit.
Replace a vague claim with available specifics; if none exist, identify the evidence gap instead of inventing a number.
For persuasive copy, use actual audience language and answer real objections without borrowing a customer's quote or claiming an outcome without permission and proof.
Then inspect wrapping and truncation in the render, preserving meaning and critical labels.
A word blacklist or readability score cannot establish usefulness.
