# Artifact design

Build or rewrite an artifact that helps its reader understand, decide, present, or act.
Carry authorized work from inspection through implementation and evidence-based correction.
Use the user's brief, source content, existing behavior, and documented system to settle routine choices without an aesthetic questionnaire.

## Route the task

Read [classification and routing](references/routing.md) before any other reference.
Classify medium, reader purpose, requested operation, and conditional features for each materially different route or section.
Then read every applicable reference in full and use its procedure.
For broad audits and substantial redesigns, inspect every applicable visual, content, accessibility, responsive, data, interaction, and document dimension even when the request names one concern.
Include a compact coverage record in the delivery note.

## Inspect and decide

Inspect representative content, data, source code, components, assets, design context, and rendered states when available.
Separate supported facts from interpretation, proposal, and unknown.
Preserve the writer's point, necessary technical detail, voice, and uncertainty.
Never invent results, customers, quotes, prices, dates, availability, capabilities, research, or proof.
Use a reversible assumption for routine gaps; ask only when missing information changes authority, truth, protected content, or the outcome.

If several structures could materially change the task, read [concept exploration](references/concepts.md) before polishing.
Compare lightweight directions by task, evidence, and stated constraints; include the existing artifact as an option.
Skip concepts when the choice is not consequential.

## Design and finish

Use the selected genre, craft, and implementation guidance to make a coherent direction grounded in the actual subject and reader task.
Use semantic HTML, existing components and tokens, and native controls where suitable.
Every visual device should explain content, evidence, sequence, comparison, or action.
Keep each presented action functional and each success state truthful.
Do not introduce a framework or remote service for a simple artifact.

Before editing an existing artifact, read [QA parity](references/qa-parity.md) and record content and behavior that must survive.
After editing, compare facts, figures, units, citations, links, content, and behavior against that record.
Render the actual artifact and inspect the full relevant path, responsive views, keyboard/focus, important states, and print/export when applicable.
Fix observed defects and recheck the affected views.
If only source or a fixed screenshot is available, state that rendering, editability, or interaction remains unverified as appropriate.

Stop when the requested scope is complete and no known material correctness, access, content-loss, or layout blocker remains.
Report what changed, what was preserved, the checks actually performed, the coverage record, and material limits.
Use [artifact-review](../artifact-review/SKILL.md) for a separate findings-only review.
